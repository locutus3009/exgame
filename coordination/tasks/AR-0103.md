# AR-0103 — Cross-mechanism epoch driver with frozen structure and quiescence flush

Nothing above Mechanism steps all mechanisms of an epoch; callers hand-roll join_all, structure can change mid-epoch, and the worker flushes on a 1 ns idle tick rather than on quiescence.

Plan: [AR-0103](../plans/AR-0103.md). Milestone: [M1](../milestones/M1.md).

- 2026-10-02T13:33:45+00:00: Driver API (before implementing): newton::Driver<T,S> { accelerator,
  Vec<Arc<Mechanism>> }; Driver::new(Arc<Accelerator>), async add(Arc<Mechanism>) -> Result<(),
  StructureError> (refuses a mechanism on another accelerator or added twice), mechanisms(), async
  step(&Epoch) -> Result<(), EvalError> which freezes every mechanism for the whole epoch and steps
  them concurrently, each wrapped as a producer counted by the accelerator. Structure: new pub enum
  StructureError {EpochInProgress, AlreadyOwned, ForeignAccelerator, DuplicateMechanism}; Mechanism
  gets try_add_body/try_connect/try_remove_body/try_split/try_merge returning Result; the existing
  infallible methods keep their signatures (callers outside owned paths) and panic on refusal.
  Freeze = per-mechanism counter + step generation checked before and after taking the inner lock,
  so a mutation racing an epoch is refused, never queued. Body ownership = process-wide set of
  claimed body WorldIds (released on detach and on Mechanism drop). Quiescence: Accelerator counts
  active producers and parked producers (a producer is parked when its step future returns Pending);
  when parked == active it sends a flush request to the worker; while producers are active the
  worker blocks instead of flushing on an empty channel; with zero producers the existing idle path
  is unchanged. Accelerator::flushes() counter for evidence. Baseline flush count
  cloth_survives_frame_time_spikes (log_flushes, 100 steps): 3902-3904 (~39/step).
