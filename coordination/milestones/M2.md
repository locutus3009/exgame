# M2 — Physics you can trust, and a first place to fly

## Outcome

M0 made quality claims checkable and M1 made the accelerator's storage and dispatch sound. Neither
asked whether the physics is right. Today no test would catch an integrator that conserves
nothing, and no test compares what the GPU computes with what the CPU source of every kernel says
it should compute. M2 closes that: the engine's answers are checked against conservation laws,
against closed-form orbits, and kernel by kernel against their CPU definitions. The three
correctness gaps M1 surfaced are fixed along the way.

This is a game project, and so far nothing in the tree is a game. M2 therefore also takes the first
step toward one, and takes it where the physics work naturally points: the owner's star-system
sketch ([setting](../../docs/architecture/planned/setting.md)) — a G-class star, a Saturn-class gas
giant, a habitable moon — says its physically consistent configuration is still to be designed.
M2 designs a first one, shows the engine keeps it stable, and puts a ship in it that a person can
fly. The verification half is what makes the second half believable: an orbit nobody has checked
against Kepler is not a place anyone should be asked to fly.

## Work

| AR | What |
| --- | --- |
| AR-0201 | GPU-versus-CPU differential oracle for every generated kernel |
| AR-0202 | Conservation property tests: momentum, angular momentum, energy drift |
| AR-0203 | Analytic orbit checks: Kepler two-body period, eccentricity and apsides |
| AR-0204 | Place a body at the island anchor's full precision |
| AR-0205 | Fatal coverage for BodyPost and a typed `EvalError::Fatal` |
| AR-0207 | A first physically consistent configuration of the star system, stable in the engine |
| AR-0208 | A ship you can fly: thrust and attitude control in that system, as a `melies` example |
| AR-0209 | Performance review and optimisation of everything M2 added |
| AR-0206 | Close the documentation drift M1 and M2 leave behind |

## Exit criteria

Each is falsifiable by a command; a claim without a recorded exit code does not count.

1. `cargo test --workspace --release` exits 0 on `main`.
2. A test runs every generated kernel kind on the GPU and on its CPU source over the same seeded
   inputs and asserts agreement within a stated per-kind tolerance; planting a one-operator
   change in one kernel's CPU source makes it fail.
3. A test steps a free jointed mechanism with no external field and bounds the drift of linear
   and angular momentum; a test steps a conservative spring system and bounds energy drift.
   Each bound is the measured value with stated headroom, recorded in the task evidence.
4. A test integrates a Kepler two-body orbit through the gravity propagator and matches the
   analytic period and eccentricity within stated tolerances.
5. A test places a body at an offset of 1e9 through the new API and shows its position relative
   to its island anchor carries no f32 rounding from that offset.
6. A test drives a degenerate motor into a BodyPost kernel and observes `EvalError::Fatal`
   naming the site, with its batch-mates unaffected.
7. A test integrates the AR-0207 system for a stated span (at least many orbits of the habitable
   moon) and asserts every body's semi-major axis and eccentricity stay within stated bounds.
8. A headless scenario test flies the AR-0208 ship from a parking orbit around the habitable moon
   to a higher orbit with scripted burns and asserts the final orbit within tolerance; the
   `melies` example builds (it is launched by the owner, never from automation).
9. AR-0209's evidence records a profile of every workload M2 added (the oracle, the Pater
   scenario, the ship scenario) with where the time goes, the optimisations made, and their
   before/after timings, each measured by a command with a recorded exit code.
10. `python3 tools/quality/check_docs.py` exits 0, and `docs/QUALITY.md` lists nothing as
   deferred that has since been built.
11. Every AR in series 02 is `done`, `cancelled` or `superseded`, with its evidence recorded.

## Out of scope

- **The determinism gate.** Its contract is blocked on the open
  [fixed-point-vs-f64](../../docs/architecture/open/fixed-point-vs-f64.md) decision, which is a
  design decision for the owner and not a task.
- **Performance budgets.** Asserting a budget needs an agreed gate machine; the device
  requirement at build time makes that a separate decision.
- **A compile-time (type-level) form of the writer invariant.** The runtime refusal from M1
  stands; a type that makes a second writer unrepresentable is a research question.
- A game renderer, scene layer or UI beyond what a `melies` example needs to show a ship and the
  bodies it flies among. The flight example is a playable test harness, not the game's front end.
- Content beyond the one star system: other systems, planetary surfaces, atmospheres.
