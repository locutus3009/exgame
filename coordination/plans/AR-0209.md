# AR-0209 plan — Performance review and optimisation of everything M2 added

Milestone: [M2](../milestones/M2.md). Task: [AR-0209](../tasks/AR-0209.md).

## Scope

Every milestone ends with a performance review and optimisation step
([roadmap](../../docs/architecture/planned/roadmap.md), "Rules every milestone follows"). This is
M2's. Runtime speed is what matters; build time is not a constraint, so heavier build-time
generation or more specialised kernels are acceptable when they buy runtime.

Deliver:
1. A profile (perf or equivalent, release build) of each workload M2 added or changed: the AR-0207
   Pater scenario and the AR-0208 ship scenario first, then the AR-0201 oracle, the AR-0202
   conservation runs and the AR-0203 orbit runs. Record per workload where the time goes (CPU vs
   GPU, flushes per step, jobs per flush, top host symbols).
2. Fix what the profile names, inside the owned paths, with before/after timings for each change
   (median of repeated runs, the command and its exit code recorded). A change that does not move
   the measured number is reverted.
3. Anything the profile names outside the owned paths, or too large for this AR, is written up as a
   proposed AR with its measurement attached, for the coordinator.
The cloth benchmarks M1 measured (`cloth_grid_stability`, `cloth_scaling`) must not regress;
re-measure them and record the numbers.

## Branch and worktree

Branch `perf/ar-0209-m2-review`, worktree `coordination/workspaces/AR-0209`, created from the
canonical checkout at the current `main`.

## Acceptance criteria

- Every workload listed in item 1 has a recorded profile and a stated conclusion.
- Every kept optimisation has before/after timings; `cargo test --workspace --release` passes.
- `cloth_grid_stability` and `cloth_scaling` timings are recorded and not worse than before.

## Evidence obligations

- Every verification and measurement command runs through `handoffctl run` and is cited by digest
  and exit code.
- Tests run in release only: `cargo test --workspace --release`.
- Push with `git push origin <branch>:<branch>` and, before submitting, verify that the pushed
  branch head equals the local head and the PR head.
- The submit note names the exact head commit, what was measured, what changed, and what remains
  unverified.
