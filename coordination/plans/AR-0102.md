# AR-0102 plan — Enforce one writer per slot per batch; repair the unsafe safety record

Milestone: [M1](../milestones/M1.md). Task: [AR-0102](../tasks/AR-0102.md).

## Scope

ACCELERATOR.md Part III: the lock-free GPU write-back is sound only if no two invocations in a
batch write the same slot. It is guaranteed by construction and checked nowhere.

Deliver:
1. Before a batch is submitted, compute the set of output slots its rows write (per message kind,
   from the same table that drives the descriptor bindings) and refuse the batch if any slot
   appears twice. Refusal fails every message in the batch with `EvalError::Backend` naming the
   collision; nothing is dispatched. Measure the cost on `cloth_grid_stability`; if it exceeds
   ~2% of step time, gate it behind a cargo feature that the newton tests enable, and record the
   measurement either way.
2. Every `unsafe` block and `unsafe impl` in crates/aristotle/src/world.rs and epoch.rs carries an
   accurate SAFETY comment. The audit found stale ones (world.rs Sync impl naming UnsafeCell and
   parked_slice_mut; World::read naming an outer guard that does not exist) and missing ones
   (World::write; epoch.rs 177, 207, 211; the epoch Sync impl covering dt but not warp). Fix the
   module-level "two doors" prose in world.rs to describe the Subbuffer door as built.

## Acceptance criteria

- A test plants two writers on one output slot in one batch and the accelerator refuses the batch; the callers receive `EvalError::Backend`; no GPU work ran.
