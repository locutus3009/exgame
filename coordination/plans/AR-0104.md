# AR-0104 plan — Accelerator worker: failure path, bounded submission, flush policy

Milestone: [M1](../milestones/M1.md). Task: [AR-0104](../tasks/AR-0104.md).

## Scope

Findings from the audit at 4d5b23c (crates/newton/src/accelerator/mod.rs):
- `shaders.dispatch(..).unwrap()` at the two flush sites panics the worker on a Vulkan error.
  ACCELERATOR.md claims failures return as `EvalError::Backend`, one submission's outcome for every
  job it carried. Make that true; the worker must survive and keep serving.
- An unconditional `eprintln!` fires on every flush. Remove it or put it behind an opt-in.
- The submission channel is an unbounded `std::sync::mpsc::channel`. Add back-pressure: a bounded
  channel (or an equivalent explicit limit) whose bound is a builder parameter, with a sane default.
- Flush policy is hard-wired. Expose the batch-size hint as a builder parameter.
- Stale comments about a Lua backend and `backend-lua`/wgsl features around lines 297-304.

Determinism (ACCELERATOR.md Part V): batch composition must change only timing, never physics.
Add a test that runs the same Newton chain with batch size forced small (e.g. 1 row) and at the
default, and requires bit-identical positions. Explicit integrators too, if they share the path.

A test seam for injecting a submission failure may live in mod.rs (cfg(test) or a test-only
builder hook); shaders.rs is owned by AR-0106 concurrently and must not be edited.

## Acceptance criteria

- A test forces a submission error; every job of that batch receives `EvalError::Backend`; a following batch succeeds on the same accelerator.
- A test with a tiny channel bound and many producers completes without deadlock.
- The batch-composition determinism test passes.
- `cargo test --workspace --release` passes.
