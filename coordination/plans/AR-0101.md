# AR-0101 plan — World capacity: refuse overflow and grow between epochs

Milestone: [M1](../milestones/M1.md). Task: [AR-0101](../tasks/AR-0101.md).

## Scope

`RawMap::insert` (crates/aristotle/src/world.rs, around lines 212-239) pushes into a growable index
`Vec` with no check against the `Subbuffer` capacity fixed at `World::DEFAULT_CAPACITY`. On the
coherent raw-pointer path `write_at` then writes past the end of the mapping, which is undefined
behaviour; on the guarded path it panics on a slice index. ACCELERATOR.md Part IV describes growth
between epochs; none exists, and the cloth benchmark hits the ceiling near 160 unknowns.

Deliver:
1. No write can land past a buffer's end, on either path. Prove it with a test.
2. Growth: when an insert needs a slot past capacity, the type's buffer is reallocated (geometric
   growth), its contents copied, the cached host pointer refreshed, and a per-map generation
   bumped. This happens under the structural write guard, which already excludes an in-flight
   submit (`Shaders::dispatch` holds exclusive guards across submit and fence). Raw indices are
   preserved, so queued messages stay valid.
3. The accelerator's descriptor sets, built once today, are rebuilt when a bound map's generation
   has changed since they were built. Check at dispatch time, under the guards it already takes.
4. Update the stale "two doors" comments in world.rs that this AR rewrites anyway (Vec<T>,
   UnsafeCell, parked_slice_mut) only where they sit in code you change; AR-0102 owns the rest.

## Acceptance criteria

- A test inserts more elements than the initial capacity of one type and reads every value back.
- A GPU test grows a map that a kernel binds, then dispatches, and the kernel reads/writes the grown buffer (e.g. `simple_sum` on slots allocated past the initial capacity).
- `cargo test --workspace --release` passes; `cargo clippy --workspace --all-targets --release -- -D warnings` introduces no new warning in owned files.
- The initial capacity may be lowered for tests via a builder knob rather than allocating 256 Ki+1 elements.
