# AR-0208 plan — A ship you can fly: thrust and attitude control in the star system

Milestone: [M2](../milestones/M2.md). Task: [AR-0208](../tasks/AR-0208.md).

## Scope

The first playable thing. Deliver:
1. A ship: a rigid body in the AR-0207 system, placed through the AR-0204 precise-placement path,
   with a control input of main-engine throttle and attitude torques, applied as forces through
   the engine's existing force path (no special case in the integrators). Mass may stay constant
   (no propellant model yet; say so).
2. A headless scenario test: start in a circular parking orbit around the habitable moon, execute
   a scripted two-burn transfer to a higher circular orbit, assert the final semi-major axis and
   eccentricity within tolerance of the Hohmann prediction.
3. A melies example that shows the moon, the giant and the ship (circles and lines are enough,
   using melies' existing primitives) and maps keyboard input to throttle and attitude, with the
   simulation stepped through `newton::Driver`. It must compile; it must NEVER be launched from
   automation — the owner runs it.
Keep the ship API small. Game feel, camera work (hitchcock) and HUD are out of scope.

## Acceptance criteria

- The scripted-transfer test passes; `cargo build --workspace --release --all-targets` and `cargo test --workspace --release` pass.
- The example's controls and how to run it are stated in the PR body for the owner.
- What was not done (propellant, camera, HUD) is listed in the evidence.

## Evidence obligations

- Every verification command runs through `handoffctl run` and is cited by digest and exit code.
- Tests run in release only: `cargo test --workspace --release`.
- Before submitting, verify the pushed branch head equals the local head and the PR head
  (M1 merged a stale head once because this was not checked).
- The submit note names the exact head commit, the negative cases exercised, and what remains
  unverified.
