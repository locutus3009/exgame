# AR-0201 plan — GPU-versus-CPU differential oracle for every generated kernel

Milestone: [M2](../milestones/M2.md). Task: [AR-0201](../tasks/AR-0201.md).

## Scope

Every GPU kernel is generated at build time from a CPU function over `Scalar`: the joint laws in
`crates/joints`, and the solver stages `pre`, `gather_term`, `matvec_term`, `gemm_term`,
`reduce_sq_term`, `assemble_term` and `body_post` in `crates/functions`. The only existing oracle,
`crates/viete/tests/kernel_differential_oracle.rs`, compares the trace run through a Lua carrier
against CPU `Differential`; nothing compares the GPU with anything (docs/QUALITY.md, deferred list).

Deliver one test file that, for every kind in `MessageKind::all()`:
1. builds seeded random but physically valid inputs (unit motors, bounded twists, non-degenerate
   joint geometry) in a `World<f32>`,
2. dispatches them through the accelerator,
3. evaluates the same inputs on the CPU source in f64,
4. asserts agreement within a per-kind tolerance stated in the file and justified by the
   measured worst case (record the measured worst case per kind in the evidence).
Prove the oracle can fail: plant a one-operator change in a CPU reference inside the test (not in
the product) and show the test rejects it; record the exit code.

## Dependencies

none. Dependencies exist where path sets overlap or where one AR's result protects another's change.

## Owned paths

- `crates/newton/tests/ar0201_gpu_cpu_oracle.rs (new)`
- `crates/newton/src/accelerator/mod.rs (test-only seam, if one is unavoidable)`

Everything else is read-only to this AR. New test files carry the AR prefix so concurrent ARs
never collide. Defects found elsewhere go into the evidence log and to the coordinator as a
request for a new AR.

## Branch and worktree

Branch `feature/ar-0201-gpu-cpu-oracle`, worktree `coordination/workspaces/AR-0201`, created from the canonical
checkout at the current `main`.

## Acceptance criteria

- Every kind in `MessageKind::all()` is covered, or the evidence names the kind and why not.
- The planted-defect run fails; the clean run passes; `cargo test --workspace --release` passes.
- Per-kind measured worst-case error is recorded in the evidence.

## Evidence obligations

- Every verification command runs through `handoffctl run` and is cited by digest and exit code.
- Tests run in release only: `cargo test --workspace --release`.
- Before submitting, verify the pushed branch head equals the local head and the PR head
  (M1 merged a stale head once because this was not checked).
- The submit note names the exact head commit, the negative cases exercised, and what remains
  unverified.
