# AR-0105 plan — Fix the two FIXME: deadlock? reproducers in the implicit solver

Milestone: [M1](../milestones/M1.md). Task: [AR-0105](../tasks/AR-0105.md).

## Scope

Two tests are ignored with `FIXME: deadlock?`:
- crates/newton/src/integrator/implicit/cache.rs, `dimension_change_reallocates_and_clears_the_hint`
- crates/newton/src/integrator/implicit/newton.rs, `topology_change_causes_no_visible_jolt`

Unverified hypothesis from the audit: around cache.rs:627-633, slot fields such as `half_slot` are
reassigned (`self.half_slot = Some(map.add(..))`) while `world.write::<T>()` is held. On a dimension
change the old `WorldKey<T>` drops in that scope, and its Drop takes `world.write::<T>()` again on a
non-reentrant lock. ACCELERATOR.md Part III names this class: remove is a structural write.

Confirm the cause first (record how), then fix it so a key is never dropped under its own type's
write guard — e.g. take the old keys out and drop them after the guard is released. Remove both
`#[ignore]`s. If either test fails for a different reason once unblocked, fix it if it is in the
owned paths, otherwise release as blocked naming the dependency.
